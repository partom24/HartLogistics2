## Exact 1.5.12 source change

In `addon/behavior_pack/scripts/urce_159_direct_sorter_home.js`, a pure `isKnownInertNativeStop(typeId)` positive material catalog (common vanilla opaque stone/brick/deepslate, planks, concrete, terracotta, inert building materials) recognizes the actual reported **`minecraft:stone_bricks`** and related conventional materials. The Hopper end is only accepted if:
- It is **the live block exactly at the Hopper's observed lateral output coordinate**, in the same dimension as the source Receiver, and has an explicitly recognized vanilla inert type.
- Live `block.getComponent("minecraft:inventory")` is callable and returns no inventory component. Known inert types unexpectedly exposing inventory, air, liquid, or unknown component states **HOLD**.
- There is a single **registered and physically complete vertical Sorter column directly below the Receiver's Hopper**, with no missing/unloaded blocks, unverified mode, shadow column, unauthorized side extraction or second source candidate.
- Every active Filter/Auto/Wildcard owner has positive live native storage destination, valid capacity and actual item-specific admission; unknown remote claim/Bulk or metadata-rich items remain outside this closed route.
- Unknown external/addon types, active native machines (e.g. **composter, jukebox, dropper, dispenser, Hopper, crafting mechanisms**), unsuitable entities, unverified inventory, actual downstream extractor or unverified native graph **remain HOLD**. This is deliberately **NOT** the false rule "every native block without a script inventory component is inert."

The local source-reachable snapshot bridge in `main.js` includes only recognized inert material terminal types as potential **single** native unknown boundaries. Before any expensive forced full graph observation, it checks the Receiver's own local registered Sorter column in memory (retaining the 1.5.11 fix for the prior >70k native reads/tick regression). It then requires a **fresh** native/visual graph reobservation, no second unknown or cycle, and exact terminal type/dimension/location equality with the local observed Hopper end.

For **all lateral native Hopper outputs**, including the newly proved inert stopper, Q4 chooses an item-specific Filter/Auto/Wildcard storage home **before any debit**. The already existing `dequeueToReceiver` journal performs a **direct endpoint credit to the verified Sorter-owned native chest**; it does **not** put cargo into the laterally pointed Hopper and does not invent a physical Sorter handoff. The exact existing Q4 writer source statements and recovery remain untouched. For a downward Hopper, original physical native Hopper→Sorter journaling remains unchanged. The pure observer contains **zero physical or durable custody writers**.

The implementation deliberately avoids **Block.isSolid**: Microsoft's stable-module docs currently mark this API property pre-release and it is not a safe shipping assumption. `typeId` and native `getComponent` are stable; the catalog is an explicit finite conservative recognition policy. **All** arbitrary inert wall blocks, arbitrary custom blocks and all network shapes are **not yet proved**.
