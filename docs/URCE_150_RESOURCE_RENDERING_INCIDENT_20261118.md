- New source regression [resource link and image integrity test](../runtime/tests/urce_150_resource_integrity.test.mjs) verifies **all** BP block material aliases, atlas-to-PNG files, CRC and DEFLATE decode, nonvanilla geometry identifiers, original filter-display client entity and BP/RP dependencies. The owner LAB's actual setting is **NOT YET KNOWN**. Bedrock client **cached resources or competing global packs** also can lead to wrong assets even when source and installer are correct. It never writes, stops BDS, restarts BDS, reads production or changes a client cache. It cannot prove that a *client* downloaded assets.
- If the doctor fails: retain the exact error message to find whether **installed** RP is incomplete or mismatched. Repair only with an appropriate versioned, protected updater after identifying the mismatch; **do not overwrite the same 1.5.0 registered pack with different bytes or bypass REFUSED safeguards**.
- If the doctor passes but `texturepack-required` is **false/missing**: client-side RP delivery is a primary hypothesis. A controlled LAB-only experiment may set `texturepack-required=true` after backing up `server.properties` and stopping BDS, then restart and reconnect to ensure clients accept the Hart RP; this is a **server setting change**, not performed here and not permission to alter production settings. The option may affect other packs, so inspect server/client pack stack first.
- If the doctor passes and the client confirms RP downloaded: inspect **client Settings → Creator → Content Log**, note the **actual missing texture/model identifier and pack name**, and check local cached server resource data and conflicting global packs. Do not indiscriminately delete all client resource data; avoid losing unrelated worlds or packs. A reconnection after confirming required pack may suffice.
- If a specific missing alias, entity texture or resource-cache defect is confirmed: fix that exact source issue and release a **new unique BP/RP version** (not reuse `[1,5,0]` under the same UUID), with an explicit verified **1.5.0 → next-version** PowerShell installer and rollback tests. The old 1.4.2 and 1.5.0 backup snapshots, including owner backup `lab-ad81804f1005`, remain protected.
