## 3. Correct outcomes: what is ruled out now, and what remains

**Ruled out as exact drop-in replacements by source and signature:**
- `transferItem` or `moveItem` for *arbitrary N-item transfer of a source slot*: no 2.7 amount parameter.
- `firstEmptySlot` for Hart's partial-stack-first destination policy.
- `contains/find` for the entirety of Hart's seeded AUTO and enchanted-book type-set semantics, without additional proof.
- `World.setDynamicProperties` as an established crash-atomic transaction spanning native inventory + virtual FIFO; the API offers no such contract.
- `onTick`, `runJob`, redstone comparator or a player inventory event as a **documented lossless generic Hopper-arrival callback**.

**Native implementation pieces worth retaining as candidates, not certified replacements:** Full-slot native moves, selective `addItem`, native slot references, physical vanilla Hopper behavior, original ItemStack clones, block states/redstone callbacks, static visuals. All still need actual engine correctness/cost proof before they can supersede manual source operations.

**Genuinely custom Hart requirements:** Filter→Auto→Wildcard priority, bottom-to-top stacked routing, live seed rules, virtual 250k Receiver FIFO, directed Collector links, queue migration, ambiguity-aware crash recovery and item-custody invariants. These could be smaller than present implementations; they cannot be waved away by the existence of a native method.

**Remaining gate:** Source-only tests can check **declared feasibility and incompatibilities**, not Bedrock slot merge/transfer behavior, runtime engine cost, durable save order, real metadata across restart, or whether a completely different native architecture fulfills the existing layout. **No replacement has been written; no LAB/world testing is authorized by this work.**
