## Narrow verified candidate change

The legacy display reconciler visits registry entries every 100 ticks. Before this change, it ran `sorterAt` and `removeDisplay` even on a native-frame Sorter; the latter scans for nearby helper entities. It now skips these custom operations for implanted Item Frames, because Bedrock's native frame owns the visual. The code still loops through the registry, so this **does not** eliminate every periodic iteration or prove any performance gain.

Startup still performs targeted proxy removal and one all-dimension orphan sweep. Native `entityLoad` and frame transition handlers continue cleanup; legacy non-frame owners keep their original ongoing repair. Source test ENGINE-34 checks 1,400 frame entries produce zero block/proxy operations in the reconciliation pass; ENGINE-35 checks startup orphan removal. Neither is an actual BDS observation.

**Do not generalize this change** to the Sorter or Collector item-observation loops without an exact native event/movement equivalence proof. Do not alter manifest, packed queues, 1.4.1 assets, production, or the owner's world. VS debugger, BDS diagnostics and native Script Profiler remain the only performance tools.
