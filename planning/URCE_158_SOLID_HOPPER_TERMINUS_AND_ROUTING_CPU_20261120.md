## 2. Why `isSolid` and inventory-component tests alone are insufficient
Bedrock reports solidity as a collision property, not proof of non-inventory or item-flow semantics; chests, dispensers and add-on machines require separate handling. Vanilla Hopper output `facing_direction` witnesses the push direction; another Hopper directly underneath can **pull** from a Hopper above even if that upper Hopper faces horizontally. A Hopper minecart or a foreign/add-on extraction mechanism is not excluded by inspecting only the forward block. Merely adding `minecraft:cobbled_deepslate` to a global list of ignored `unsupported_native_boundary` codes would hide this safety distinction.

## 3. Source-only prototype (not connected to installed engine)
`planning/src/urce_u1_solid_terminal_probe.mjs` walks only a single Receiver-native-Hopper output path, reads the facing direction on every visited Hopper, and tests the **below-Hopper pull branch for horizontal outputs**. It recognizes a deliberately narrow, explicit set of known inert *vanilla* structural blocks (including cobbled deepslate); no custom block is presumed inert. Air is separately classified as a terminal. An apparent pull branch, container, Sorter, Transporter, unloaded read, unknown orientation, loop or over-budget walk cannot yield `TERMINAL_INERT`. Hop and read caps are explicit, calls are read-only. Every result has `coverageComplete:false`, `mayAuthorizeLink:false`, `mayTransferCargo:false`, and `persistPermitted:false`.

`runtime/tests/urce_158_solid_terminal_probe.test.mjs` exercises the actual cobbled-deepslate class, all six Bedrock facing values used by the current model, alternate rotations, real-air terminal, chests/barrels/Sorters/dispensers/foreign blocks, a Hopper pulling from below, loaded unsupported/unknown below, read failures, a verified Hopper cycle, hop/read limits, and an intermediate lower-Hopper pull branch. The active development workflow now runs this **source-only** test; it does **not** change the reviewed planning/runtime parity pair or installed 1.5.7.

**Important boundaries before any gameplay candidate:**
1. Integrate only after graph-level source tests prove composed routes (including Collector→Receiver links and source-local Hopper pulls), branches and merges, unloading and existing Q4 links; a local terminal probe alone is not a complete absence-of-return-path proof. Static inert types can be extended only with native semantic evidence. Hopper minecarts and foreign extraction remain unproved coverage and may force HOLD.
2. Any runtime integration can change a Receiver from HOLD to SAFE_SNAPSHOT and allow the original Q4 drain. Therefore it is a **custody-affecting gameplay change**, not a diagnostic-only tweak. Require a **separate versioned** candidate, exact immutable 1.5.7 predecessor, checked protected writers, source regression and native-call budgets, exact-head CI, Windows synthetic installer/rollback, a read-only stopped copied-LAB preflight and a user-controlled paused LAB test *before* releasing any queue. Do not overlay 1.5.7 bytes.
3. Avoid repeatedly scanning all Receivers/global topology for each routing item. The source probe can double the native reads of a long Hopper walk by examining below-Hopper pull candidates; it is **not** performance-acceptable by default. Design a source-scoped bounded/revision-aware proof with invalidation on any relevant world or registry changes; if freshness is unknown, HOLD. No positive cross-tick cache without a proven invalidation contract.
