# URCE 1.5.6 — owner BDS 1.5.5 native tick-clock regression (2026-11-20)

## Evidence and root-cause boundary

Directly parsed full owner-provided `diagnostics_2026-11-19_20-17-59.0/.1/base.mcstats` files; one contiguous owner session spans native tick IDs **874221552–874222007**, comprising 456 tick samples. Measured native `script_tick` mean **41.886ms**, p50 **27.154ms**, p90 **100.685ms**, p95 **132.206ms**, p99 **171.229ms**, max **217.462ms**; **73/456 >50ms** (16.01%), 47/456 >100ms (10.31%). `level_tick` p50 **30.088ms**, p90 **42.388ms**. The latest owner 1.5.4 post-restart baseline p50 22.073ms, p90 29.838ms, max 116.993ms (280 samples), so 1.5.5 appears substantially worse under the capture conditions. Different duration, server age/position and profiler instrumentation remain possible confounders.

The new 1.5.5 JS CPU capture is **29.8951s sampled**, 1,663,478 samples; `schedulerTick` inclusive **17.295s (57.9%)**, `logisticsTick` **10.749s (36.0%)**, native `System::currentTick` **10.775s self (36.0%)**, `Dimension::getBlock` **8.801s self (29.4%)**, native `World::getDynamicProperty` only **1.165s self (3.9%)**. The **11.090s inclusive** `sorterJournalPending` source function includes almost all of the expensive `System.currentTick` accessor. That source gate was added in 1.5.5 to replace the previously costly native journal property read. The previous 1.5.4 after-restart profile attributed **9.569s (46.3%)** to `World::getDynamicProperty` over its own 20.671s capture. This establishes the *mechanism* of the new regression without treating profiler hit counts as native call counts. JS and TS are two representations of the SAME latest CPU capture and must not be summed.

## Correction

Use **only a JS integer scheduler-pass counter** with the already registered `system.runInterval(schedulerTick,1)`; no native time getter. A successful journal read is reused for up to 20 subsequent active scheduler passes; any failed read stays pending/unknown and retries on the next pass. A Hart write changes cached state synchronously, while failure invalidates it. Integer overflow invalidates and resets. The explicit new-transfer `saveJournal(tx)` still checks NATIVE journal persistence freshly, refusing unresolved saved data even when the idle cache is clear. Receiver `logisticsTick` still reads the native journal each tick. The original physical debit/credit `safeMovePartial`, journal recovery and Q4 queue writer bodies remain unchanged. Full route discovery must remain transporter-optional for arbitrary player layouts (#86); this perf fix adds no broader scans or mandatory Transporters.

Node tests execute the actual main.js source seam under a fake `system.currentTick` property that THROWS when accessed, across 200 idle scheduler calls, crash-journal recovery, 20-pass expiry, native read/write failure and unrelated Receiver native checks. Strict LAB source upgrader pins exact 1.5.5 predecessor SHA `bc4c1674767cb0e79e90472b3cde0d73531246d4`, exact three approved blob IDs, same BP/RP identities/API, and synthetic Windows installation/rollback proof. **Native Bedrock 1.5.6 performance is not verified until owner chooses the stopped copied-LAB install and obtains new captures**. No raw world/CPU profiler attachments have been added to source control.
