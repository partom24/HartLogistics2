## Source data and reason for this increment

The owner uploaded two quiet VS Code profiler/Bedrock diagnostics pairs for 1.5.4 before and after a server restart, the latter captured roughly five minutes after server start. Earlier 1.5.4 (.mcstats combined 192 samples) script_tick: mean 35.286ms, p50 25.018, p90 64.428, max 170.203ms, 12.5% above 50ms. After restart (two consecutive files, combined 280 samples): mean 26.336ms, p50 22.073, p90 29.838, p95 53.620, max 116.993ms, 5.36% above 50ms and 2.86% above 100ms. Thus typical pressure improved but tail spikes remain; the captures do not prove a monotonic startup-age slowdown. JS CPU profile after restart (20.671s sampled): schedulerTick 13.543s (65.5%), logisticsTick 5.708s (27.6%), `World::getDynamicProperty` 9.569s (46.3%), and `processColumn` 3.782s; a single native `getDynamicProperty` node under schedulerTick accounted for ~8.835s. CPU hitCounts are sampling attribution, not native-call counts. Script and level timing categories should not be naively interpreted as a confirmed total TPS.

## Exact reviewed 1.5.4→1.5.5 changes

- Only three pack files differ: BP manifest, RP manifest (new 1.5.5 identity; UUIDs and accepted 4x4 visual assets unchanged), and the original `main.js`. No other behavior-pack modules, Q4 source writer bodies or world/item serialization changes.
- The idle Sorter `schedulerTick` uses a **bounded 20-tick journal-state audit** instead of reading a global dynamic property every tick. This cache never claims native inventory or route safety and starts **unknown/pending** until an actual native read.
- All successful Hart journal writes and clears **immediately update** the idle gate. Native write/read errors fail closed rather than clearing a pending journal.
- **Crucial independent hard-fence:** When `saveJournal(tx)` opens a NEW physical transaction, it always freshly reads the actual native `JOURNAL_KEY` and REFUSES to overwrite any unresolved prior journal, regardless of cached idle state. `safeMovePartial` original debit/credit writer remains byte-for-byte unchanged. Receiver `logisticsTick` still reads the native physical journal every tick; no Q4/receiver recovery guard is cached.
- Fail-closed source-executed tests cover 200 idle scheduler ticks, startup with a pending journal, immediate Hart write/clear, out-of-band foreign pending journal detection at expiry, refusal of overwrite even before expiry, read/write failures and independent receiver journal checks.
- **Potential residual limitation:** An unexpected out-of-band journal change can leave the *idle scheduler* cache behind for a maximum of 20 ticks, but cannot authorize a physical debit because new transfers independently revalidate native persistence. This does not certify unobservable world changes for general topology routing.
